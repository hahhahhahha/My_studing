# 视觉策略环境：真实回执、规则适配与共享奖励工程入口

本入口只做校准／验证角色的工程检查，不构成正式策略比较、独立审计或完整实验。没有学习模型、Torch、GPU、优化器、训练或保留测试调用。原 FIFO、广播、环境基础源码与既有成功记录不修改；通过新增子类和入口接入。

## 信息与记账边界

新增事件账本只有已发生的接纳／完成／丢弃事件。接纳回执包含任务 ID、用户、服务器、实际接纳时刻以及**元数据预测的服务秒数**，不包含实测服务要求、未来完成时刻或未来剩余工作量。四种方法都可取得同一动作前观测和本控制器已接纳任务的历史；JSEQ 自行使用这段历史，学习输入仍是共同的19维特征。相同可用信息不等于所有方法必须使用相同内部状态。

动作前 critic 不读当前动作或当前动作执行后的回执。共享训练奖励的队列项缓存**动作前的服务器当前预测工作量**；它不是实际剩余服务时间，也不作为新的即时信息送入 actor、QL 或 critic。实际任务完成时延来自过去的完成回执：完成时刻减真实外生到达时刻，包含决策等待与上传等待，不由预测器生成或截断。丢弃是执行缓冲真实拒绝事件，固定训练罚项与最终 drop 指标分开。

严格阶段顺序为：动作前 observe → apply → settle 到下一个物理决策边界 → 共享 reward → 下一次 observe。重复／遗漏结算、提前观察、重复执行均拒绝；阶段故障不能续写原实例。每个回执只结算一次，完成／丢弃在 `(动作时刻, 下一边界]` 内记账，恰好在右边界发生的事件不会重复计入下一段。当前链路有严格正上传时长；零时长导致同起点事件时拒绝而不静默丢弃。

## 两个规则方法

- Score-softmax：使用与学习特征相同的服务器完成代价分数 `1/(1+预测代价/固定时延尺度)`，按固定温度0.25做 softmax。
- JSEQ-A 视觉适配：从实际被检索到的陈旧预测队列及其**源时间戳**起步，依时序加入该源时刻之后的本控制器接纳预测工作量，每台服务器按一秒工作／物理秒推进；接纳时刻等于源时刻的任务已经包含在广播中，不重复计入。不存在隐藏后台任务回执。使用相同上传／服务代价代理，仅替换其中的等待项，再采用固定温度0.25、代价标准差下界0.001秒的 softmax。

JSEQ 的秒级预测工作适配不是原论文算法的精确复现。上述温度等仍是工程候选值，不依据 QLA 相对优势选择，也尚未冻结为正式协议。

## 时间终点与尚未解决的训练事项

80个50ms决策的请求生成范围是 `[0,4)` 秒，动作在0.05至4秒执行，最后动作的奖励结算区间到4.05秒。共同 drain 的终点固定为4+30=34秒，不能在4.05秒基础上再追加30秒而隐式延长。

drain 中完成／丢弃仍计入最终未截断指标与回执守恒，但当前工程入口**不把它们重新加入学习奖励**。未完成任务的训练终末罚项、有限训练窗口的异步信用分配与最后一步 bootstrap／done 语义尚待校准／验证预实验制定和冻结；正式训练前必须解决并独立检查。当前两规则没有训练，因此不能把工程奖励记账当成 QLA/PPO 学习效果的证据。
