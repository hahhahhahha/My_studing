# 视觉路线B：FIFO执行与预测压力广播边界（工程基础）

`scripts/predicted_fifo_feedback.py` 把连续FIFO执行接到周期广播。执行请求含实际配对服务时长，仅供执行层决定完成事件；每个任务另保存由校准池冻结预测器和元数据得到的预期服务秒。

每个广播时刻先推进上传/服务事件，再生成以下服务器摘要：

- 等待队列中任务的预测服务秒之和；
- 正在运行任务的 `max(预测服务秒－已运行秒,0)`；
- 已观察到的等待任务数及服务器忙碌标志。

摘要计算不读取实际服务或尚未完成任务的真实剩余时长。预测耗尽但实际仍在运行时，估计剩余量可以为零，但忙碌标志仍为真；这是近似误差，不用实际未来服务时间修正。完成事件改变了已观察到的运行/排队状态是合法反馈，不是提前提供未来真值。上传未完成的请求不属于服务器计算队列。以上近似仍需校准/验证预实验核对，不能预设准确或更有利于某策略。

所有方法最终只能获得同一个不可变的 `RetrievedFeedback` 数据面，不接收执行对象。可用摘要满足 `source_time ≤ now－nominal_delay`，同时返回真实source age；名义延迟零仍可能读取半个广播周期以前的摘要。启动阶段没有足够旧的摘要时明确标记missing，source/age为None，不虚构负时间戳或冒充新鲜信息。初始化known-empty值只是缺反馈占位，最终actor缺失标志编码须统一冻结。

广播时间用整数序号乘精确十进制周期，检索截止时间同样按十进制计算，避免0.3−0.1的浮点误差错过0.2广播。任务与广播同刻时沿用FIFO的“先完成/接纳，再广播”；同一决策时刻必须先取得观测，再提交当前动作。方法适配器不得把当前动作后的队列/需求泄漏到当前actor或critic。
