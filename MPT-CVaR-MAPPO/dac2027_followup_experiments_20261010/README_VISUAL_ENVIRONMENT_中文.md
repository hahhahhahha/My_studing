# 视觉路线B：共同日程、上传链路与动作前观测（工程接入）

新增 `visual_request_schedule.py`、`visual_upload_link.py` 和 `visual_environment_adapter.py`。它们连接已验证的实测执行目录、校准池冻结预测器、真实10秒KAIST插值与预测压力广播；尚未接入正式学习算法、奖励与critic。

共同日程在方法运行前生成并持久化：任务ID、用户、实际到达秒、图片ID、配对测量会话和分类分配uniform。各随机流与策略动作独立，不截断Poisson请求；突发概率与倍数显式记录，给定总请求率按无条件平均率解释。每个方法使用相同日程与逐任务两CPU配置的服务真值对，路由不会推进另一条服务随机流。当前工程入口只允许校准/验证角色，不启用测试测量。

任务在真实到达后的第一个50ms决策点进入当前可观测请求集合。`observe()` 返回不可变的全用户动作前数据面，重复读取不会推进到下一批；它只包含已到达任务的元数据、校准预测、模拟上传估计、当前位置、先前portfolio、用户既有上传等待、共享陈旧摘要和联合参考预测需求。不含测量会话、分配uniform、真实服务时长、未来图片或未来位置。最终actor/QL及current-action-free critic必须只从该数据面构造输入，不能拿到环境/日程/执行目录对象。

`apply()` 对所有用户portfolio先做一致性检查，再用共同uniform抽取服务器、逐用户串行上传、并在上传完成后进入有限FIFO。硬缓冲约束在实际到达服务器时执行，不用未来服务真值筛服务器。缺少动作前观测、重复apply、故障实例继续执行、已结束后延长drain均被拒绝；执行故障不自动追加重试。不同动作导致不同上传排队/服务器队列是结果，不同外生请求不是方法优势。

时延以 `完成秒－原始实际到达秒` 计，包括等待下一次决策、客户端上传排队、传输、服务器等待与实际服务。FIFO内部接收时刻是决策发送时刻，不能把它的内部时延误当端到端任务时延；输出主latency已经加回决策等待。响应项未测且暂忽略，控制器运行时间尚未计入，不能称真实端到端实测。

## 工程链路参数与假设

候选链路采用2MHz/用户、915MHz、0.25W、天线增益4.11、最小距离1m、自由空间损耗及Shannon速率；噪声**功率**显式为1e-10W，SNR中不平方。旧代码的 `noise_w**2` 与此不是同一数值链路，旧代码/结果不修改，也不宣称新协议原无线参数数值未变。新视觉协议尚未冻结，此选择按量纲明确而非QLA优势作出，须在校准/验证工程pilot中核对并披露。

每个用户一条串行上传队列，用户之间假定正交带宽、无服务器侧无线干扰争用（30用户最多对应60MHz资源假设）；没有测真实网络。速率使用路由决策时的用户位置并在该次上传内保持，串行等待期间不预读未来移动位置。所有方法一致。不能把这种模拟信道当部署容量；pilot必须报告每用户请求/上传负荷、上传等待/吞吐是否符合所声明业务。
