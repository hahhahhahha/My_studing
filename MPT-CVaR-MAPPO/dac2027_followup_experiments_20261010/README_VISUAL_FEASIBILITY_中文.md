# 视觉负载／上传可行性：校准—验证工程诊断

本检查不是模型训练、算法性能比较或正式协议冻结。只用校准池拟合过的服务均值与JPEG元数据、验证图片的JPEG元数据作诊断，以及显式候选训练位置窗0–500秒；不接触保留测试图片／时长，不重新运行服务测量或验收导出。

## 预先规定的计算口径

保持30用户、4个虚拟服务器、CPU1T／4T各2个，50ms决策、训练窗几何与seed123位置、2MHz／用户默认模拟链路不变。四个虚拟服务器的总服务能力标尺为`C=Σ_j 1/mean_calibration(S_j)`；它不是四设备的实际联合吞吐实测。按原方案诊断rho=.60/.75/.85、总请求率`lambda=rho*C`，均分到30用户。JPEG大小与时间／位置独立抽样是现有模拟假设；所有图片保留，不删除大图。

在整个候选500秒训练位置窗的10,000个真实50ms决策点，计算每用户到各服务器的速率。对每个用户计算三种每请求平均上传占用：

- 最快链路下界：`mean_bits * mean_t(1/max_j(rate_tuj))`。
- 均匀路由诊断：`mean_bits * mean_t(mean_j(1/rate_tuj))`。
- 最慢链路上界：`mean_bits * mean_t(1/min_j(rate_tuj))`。

再乘每用户请求率得到串行上传工作负荷比。若**最快链路下界**都大于等于1，则该500秒窗内的期望上传工作量已超过单用户可用上传时间，不能靠路由消除这一期望工作缺口。均匀或最慢链路超过1不等于所有策略都必然不可行。有限窗口、突发、队列初态与统计波动仍需实际工程重放；这些比值不是稳定性证明或尾时延验收。

验证图片只用于重复上述载荷诊断，服务能力仍由校准池固定；不按验证服务均值重新拟合容量，更不按策略成绩挑参数。带宽规模诊断仅按现有模拟链路的线性带宽项换算，不更改实际配置；该换算保持当前噪声功率假设，并不是可直接用于真实无线部署的频谱预算。

2MHz／用户正交且无用户间干扰隐含30用户总计60MHz的理想化并行资源。若rho标尺需要每用户多帧／秒，必须称为高频视觉帧压力测试，而不是典型低频校园拍照服务；所有网络、独立虚拟服务器假设需披露。

## 共同训练预算的候选划分

仅准备候选：10,000决策步分为10个闭合episode×1,000步（每个50秒到达窗），每闭合一次才允许更新；两学习方法完全同预算／更新次数。与每episode固定30秒drain搭配时，动作物理时长共500秒、独立episode执行时长共800秒，后者不能省略。episode有独立初始队列，不是一个连续部署轨迹；10次更新能否充分学习仍需实际模型pilot，不能提前认定。
