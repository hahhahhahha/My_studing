# 干扰标定报告：单节点单独运行 vs 四节点并发运行

日期：2026-10-14。目的：确定"四节点共驻"是否因共享 CPU 竞争显著拉慢服务时间（compute_s），并检验亲和性隔离能否消除。这是诊断性标定，不是论文正式性能结果。

## 方法

- **严格配对**：每个节点在三种条件下处理**完全相同的 200 张图片**（`data/calibration_images.json` 按内容哈希排序前 200 张）、相同的预热（warmup=20）、相同的推理线程数（1/1/2/2）、相同的权重（ResNet-18，SHA `f37072fd...`）。唯一差别是"其他 3 个节点是否在跑"以及"是否做了亲和性 pin"。
- **测量量**：`compute_s` —— 复用 `systemlab.edge.VisionEngine` 的墙钟计时（forward + 有限值检查 + argmax），**不含** FIFO 等待、HTTP/网络与客户端开销。另记录每进程 CPU 时间（`time.process_time`）与墙钟之比。
- **三条件**：
  1. `solo`：一次只跑 1 个节点进程。
  2. `concurrent`：4 个节点进程同时跑（无亲和）。
  3. `concurrent_affinity`：4 个节点进程同时跑，各 pin 到**不重叠的物理核**。
- **重复与随机化**：每条件 3 次重复，执行顺序由 `seed=20261014` 预登记随机化（共 18 个单元）。
- **硬件拓扑**（本机实测）：8 物理核 / 16 逻辑核，SMT 兄弟连续配对（物理核 k = 逻辑核 2k、2k+1）。亲和 mask：edge0→core0(0x3)、edge1→core1(0xc)、edge2→cores2,3(0xf0)、edge3→cores4,5(0xf00)。
- 失败尝试保留：`interference_calibration_affinity_attempt_01_broken/`（亲和调用缺 argtypes 导致 SetProcessAffinityMask 失败，已修复并重跑）。

## 结果（median 三次重复的平均；括号为相对 solo 的变化）

| 节点 | 线程 | solo 中位 ms | 并发中位 ms | 亲和中位 ms |
|---|---:|---:|---:|---:|
| edge0 | 1 | 28.06 | 35.55 (**+26.7%**) | 29.25 (+4.2%) |
| edge1 | 1 | 27.72 | 35.12 (**+26.7%**) | 31.83 (+14.8%) |
| edge2 | 2 | 19.20 | 21.90 (**+14.1%**) | 18.47 (-3.8%) |
| edge3 | 2 | 19.43 | 21.77 (**+12.1%**) | 23.16 (+19.2%) |

P95 趋势与中位数一致。三次重复间各节点中位数波动 < 1 ms（除 edge3 亲和 22.8–23.7 ms），观测差异稳定，非噪音。

CPU/墙钟比在三种条件下相近（1 线程 ≈0.98、2 线程 ≈1.97）。注意：**该比值相近不能推出"CPU 时间不变"**——若墙钟上升而比值相同，CPU 时间也上升（例如 edge0 solo CPU≈6.26 s/wall≈6.42 s，concurrent CPU≈7.94 s/wall≈8.16 s，两者都约 +27%）。本标定未采集性能计数器或频率观测，因此**不能据此归因缓存、抢占或睿频**，只能陈述"墙钟分布随条件发生观测变化"。

## 结论

1. **观测到服务时间变化**：无亲和并发下，1 线程节点 compute 中位上升约 **27%**，2 线程节点约 **12–14%**。这一观测与 M1 低负载→高负载的 34–37% 增长方向一致，且本标定用同一批图片、同预热、同线程数做了配对对照；但**只能主张"在这些记录条件下观测到变化"**，不能主张已唯一确认共享 CPU 竞争、或已排除时段/缓存/频率因素。
2. **亲和 pin 改变观测分布**：edge0（+27%→+4%）与 edge2（+14%→−4%）回到接近 solo；edge1（+15%）与 edge3（+19%）仍有残差。残差重复稳定，但**不足以证明其机制**（缓存层级 / 睿频等需更直接证据）。
3. **对正式实验的含义**：在本机（8 物理核）上四节点共驻会引入可观测的服务时间扰动。若要论文做可信的性能归因，需要更直接的证据（缓存域感知亲和、性能计数器、或真正隔离的资源如 Docker cpuset / 多物理机）。**不能从"服务变慢"推出对任何方法的收益是保守估计**——共驻可能对不同策略产生不同方向的偏差。

## 局限（因果边界）

本标定的数据足以支持"观测到条件间差异"，但**不足以**支持强因果或机制结论：

- 无 ready barrier：worker 在模型加载与 warmup 后才 `start_event.wait()`，主进程在 `p.start()` 后立即 `set()`，不保证各 worker 统一开始测量。
- 无可核测量窗重叠：仅记录 wall_s/cpu_s，无各进程绝对起止时间与 PID；2 线程与 1 线程 run 时长不同（约 5.3 s vs 8.1 s），不能证明全部 200 张图都在其他三节点持续测量下执行。
- PLAN 后写：执行全部结束后才写 PLAN，虽有 seeded shuffle 可重建顺序，但 PLAN 本身不证明运行前已不可变预登记。
- CPU 量非逐图：`process_time` 包围整个 200 图循环（含文件读取、预处理、forward、循环），rows 只记录 compute_s/preprocess_s，无逐图 CPU 时间。
- 拓扑/来源证据有限：未保存原拓扑查询输出、实际 affinity 回执与历史主机 runtime；review 已只读复测当前 8 核连续 SMT 配对，但不测缓存域，也非历史执行时证明。
- 驱动非 fail-closed：worker 捕获异常写 error 但不重抛；此驱动不直接作为后续可信采集入口。

## 数据

- `interference_calibration/PLAN.json`：预登记方案、亲和 mask、图片列表。
- `interference_calibration/run_NN/{edgeX}.json`：每单元每节点的逐张 compute_s / preprocess_s / CPU 时间。
- 分析脚本：`drive_scripts/run_interference_calibration.py`（spawn 多进程，亲和用 SetProcessAffinityMask）。

本标定未修改模型、奖励、图片角色、负载规则或正式预算，未运行 E1，未新增监控自动化。
