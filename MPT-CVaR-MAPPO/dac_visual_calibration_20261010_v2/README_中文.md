# V2：视觉服务分布校准修复

本阶段不是开发或训练视觉识别模型。使用官方预训练 ResNet-18 IMAGENET1K_V1，开发的是完整请求服务时间的经验模型，供之后的卸载模拟器校准使用。本实验不训练 QLA、不修改论文，也不证明 QLA 的收益。

## 为什么另建 V2

V1 的 CPU-4T 完整服务 P99 验收失败。V1 抽样只平衡类别，校准和验证的大图比例不同；两类会话也先后分开执行。V1 的失败报告与 23000 条计时原样保留，不能改写成通过。

## 冻结的新方案

- 数据和权重只读复用 `../dac_visual_calibration_20261009/`。V1 的 2000 张校准图、5 次配对计时用于建模；原 500 张验证图已用于诊断，排除出新的确认性验证。
- 从未使用的官方 train 图中选择 2000 张新验证图。排除与 V1 所有选定角色的相同 SHA256 或 dHash64 距离不超过 2 的图，再排除新候选间近重复。
- 尺寸层固定为 ≤0.25MP、0.25–0.5MP、0.5–1MP、1–2MP、>2MP。每层尽量至少 25 张，余量按合格库存比例分配；层内按类别比例抽取，使用固定种子 20261010。
- **目标人口**是去重后、未使用的官方 train 库存；不是校园地标真实请求分布。过采样层按库存比例加权，不能把其抽样比例当作自然请求比例。
- 条件经验模型：在同一尺寸层内，以 `(log2(像素数), log2(JPEG字节数))` 的欧氏距离，选择最多 20 张最近的 V1 校准图；邻居、5 次会话等权，保留每张图两种 CPU 配置的配对阶段耗时。不通过验证耗时调整邻居数、距离、阈值或模型。
- 层内类别配额经整数取整后，各“尺寸 × 类别”格的纳入比例不同。因此每个新验证请求权重为该格库存图数除以（总合格库存图数 × 该格验证图数）；所有非空格均有验证图覆盖。预测分布和实测分布采用同一目标权重。输入条件不属于服务时延标签。
- 最近邻距离超过 2（log2 二维距离）标为缺乏局部支持，任何此类请求均不允许整体通过；不静默回退或剪裁输入。
- 3 个确认会话，每会话 2000 张新验证图和 200 张固定参考图，均测 CPU-1T/4T。参考图来自 V1 校准，**只诊断会话漂移，不拟合修正系数**。每 200 张验证与 20 张参考组成一轮，轮内随机交错数据角色并反平衡 CPU 顺序；所有计时串行、独立子进程。
- 每块 200 次预热，FP32、batch=1、eval/inference_mode。CPU-1T 使用 CPU0；CPU-4T 使用 CPU0/2/4/6，interop=1。完整计时含 JPEG 解码/RGB、官方预处理、推理、argmax 和响应字典，不含磁盘、网络、排队或控制器。
- 会话开始至少间隔 15 分钟，运行前检查空闲负载。保留慢请求，不因结果删图、删会话或重跑。
- 验收沿用均值 10%、P95 15%、P99 20% 的相对误差容差，分母为实测值。两配置 6 项均通过且无缺乏支持、完整性错误，才测 V1 原保留测试池 1000 张 × 两配置 × 5 会话。确认计时 13200 条；保留测试 10000 条，参考不混入验证统计。
- 报告图片与会话的交叉重采样区间：在“尺寸 × 类别”格内重采样图片，并整体重采样会话。稀有格只有少量独立图片，不宜把重采样区间解释为对任意长尾的充分覆盖。重复计时不等于新增独立图片。验证失败即归档停止，不能自动调整或补测直到通过。

## 运行入口（现有环境，无需安装）

在 PowerShell 中执行以下只读检查，独立审计员必须原样执行：

```powershell
& 'X:\anaconda\ANACONDA\python.exe' -X utf8 'X:\Yi-one\workspace\MPT-CVaR-MAPPO\dac_visual_calibration_20261010_v2\scripts\runner.py' check
```

预备登记一次执行 `runner.py prepare`，生成冻结划分、模型、预测与协议；`check` 不测服务、不修改冻结材料。入口审计通过后，由本任务启动一个隐藏的 `runner.py run` 进程。不能重复启动、覆盖计时或从失败状态自动恢复。

## 证据边界

这是单机器 CPU 配置的重复测量，不是多设备部署、地标识别精度验证或模拟器队列验证。对输入范围和测量条件的适用性需要看实际验收；通过后才能接入模拟器，并另做队列守恒、时延统计与策略收益验证。相同预训练视觉网络在此期间不更新任何权重。
